# 🤝 Contributing to AppSprint Solution Challenge 2025

Welcome to **AppSprint Solution Challenge 2025!** 🎉

This guide explains how to participate in the hackathon using this repository.

---

# 🚀 Getting Started

## 1. Fork this Repository

Click the **Fork** button in the top-right corner of this repository.

This creates your own copy where you'll build your project.

---

## 2. Clone Your Fork

Replace `YOUR_USERNAME` with your GitHub username.

```bash
git clone https://github.com/YOUR_USERNAME/AppSprint-2025.git
cd AppSprint-2025
```

---

## 3. Create Your Mobile Project

You may use **any mobile development framework**.

### Option A — Flutter (Recommended)

```bash
flutter create my_app
cd my_app
```

---

### Option B — React Native (Expo)

```bash
npx create-expo-app my_app
cd my_app
```

---

### Option C — React Native (CLI)

```bash
npx @react-native-community/cli init MyApp
cd MyApp
```

---

### Option D — Native Android

Create a new Android project using **Android Studio**.

---

### Option E — Native iOS

Create a new iOS project using **Xcode**.

---

### Option F — Any Other Framework

You are free to use any mobile framework that meets the challenge requirements.

Examples include:

- Ionic
- Kotlin Multiplatform
- .NET MAUI
- Capacitor
- NativeScript
- Other mobile technologies

---

# 📁 Repository Structure

Organize your repository clearly.

Example:

```
AppSprint-2025/
│
├── README.md
├── assets/
├── src/
├── lib/
├── screenshots/
├── presentation/
└── docs/
```

Your structure may differ depending on the framework you choose.

---

# 📝 Update Your README

Replace the starter README with the provided **README_TEMPLATE.md**.

Your README should include:

- Project Name
- Team Information
- Problem Statement
- Solution
- Features
- Screenshots
- Tech Stack
- Installation Steps
- Demo Video
- APK / Build Download

---

# 💾 Commit Your Work Regularly

Commit meaningful progress throughout the hackathon.

Example:

```bash
git add .
git commit -m "Initial project setup"
git push origin main
```

Good commit message examples:

```
Add authentication
Implement dashboard UI
Connect Firebase backend
Fix login validation
Improve profile screen
Add offline support
```

Avoid commit messages like:

```
Update
Final
asdf
test
```

---

# 📦 Create a GitHub Release

Before submission:

1. Open your repository.
2. Click **Releases**.
3. Click **Create a new release**.
4. Upload your APK.
5. Publish the release.

---

# 🎥 Demo Video

Record a demo (maximum **2 minutes**) showing:

- The problem
- Your solution
- Main features
- Application walkthrough

Upload it to YouTube (Unlisted/Public) or Google Drive.

---

# 📤 Final Submission

Your submission should include:

- ✅ Public GitHub Repository
- ✅ Updated README
- ✅ APK / Installable Build
- ✅ Demo Video
- ✅ Presentation Slides
- ✅ Submission Form

---

# 📋 Best Practices

We encourage participants to:

- Keep commits meaningful.
- Write clean, readable code.
- Organize folders properly.
- Document important features.
- Test the application before submission.
- Maintain a clear Git history.

---

# ❌ Avoid

- Uploading API keys or secrets.
- Committing unnecessary build files.
- Using another team's project.
- Submitting private repositories.
- Waiting until the final day to push changes.

---
